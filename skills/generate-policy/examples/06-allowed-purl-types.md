# Example 6: Allowed PURL Types (PASS/FAIL Toggle)

This policy validates that all packages in a CycloneDX SBOM use approved PURL types. It demonstrates toggling between PASS and FAIL by changing which package types are in the allowed list.

---

## Instruction for generate-policy skill

```
Create a policy set called "purl_type_policy" that validates allowed PURL types
in a CycloneDX SBOM. Put all output in the current working directory under
purl_type_policy/.

Public key (save as cosign.pub in the policy set directory):
-----BEGIN PUBLIC KEY-----
MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAEvNwsVZ3wDJ4VexmmrYvxxNDOuuNs
HgJrCj+favVDoHXuxelanurZGOor1nCoTytfwEFZc5HgcLr+C4lgksRBAA==
-----END PUBLIC KEY-----

Rule: allowed_purl_types
- Iterate over components in CycloneDX SBOMs (via sbom.cyclonedx_sboms)
- Skip components that have no purl or an empty purl
- Parse the PURL type from the purl string (the segment between "pkg:" and the first "/")
- Check the type against data.rule_data.allowed_purl_types
- Deny if the type is not in the allowed list
- Severity: failure

Create TWO policy configurations so the demo can toggle between pass and fail
without editing any files:

1. policy.yaml — references a data/ directory where allowed_purl_types includes
   "generic" along with "rpm", "npm", "golang", and "pypi". This should PASS
   because the SBOM's only package is pkg:generic/busybox@1.37.0.

2. policy-strict.yaml — references a data-strict/ directory where
   allowed_purl_types is ["rpm", "npm", "golang"] (no "generic"). This should
   FAIL because the "generic" type is not in the allowed list.

Both policy files should reference the same policy rule directories — only the
data source differs.

After generating, run OPA tests to verify all pass, then demonstrate both
commands:

  # PASS
  cd purl_type_policy
  ec validate image --image <IMAGE> --policy policy.yaml \
    --public-key cosign.pub --ignore-rekor --output text --info

  # FAIL
  cd purl_type_policy
  ec validate image --image <IMAGE> --policy policy-strict.yaml \
    --public-key cosign.pub --ignore-rekor --output text --info
```

---

## Expected Results

### With `policy.yaml` (permissive): ✅ PASS

`"generic"` is in the allowed list, so `pkg:generic/busybox@1.37.0` is accepted.

### With `policy-strict.yaml` (strict): ❌ FAIL

Only `rpm`, `npm`, and `golang` are allowed. The violation message should be:

```
Package pkg:generic/busybox@1.37.0 has PURL type 'generic' which is not in the allowed list
```

### Toggling

To switch between pass and fail, either:
- Use `--policy policy.yaml` vs `--policy policy-strict.yaml`
- Or edit `data/rule_data.yaml` to add/remove `"generic"` from `allowed_purl_types`
